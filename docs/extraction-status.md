# 文档抽取状态（L2）

> 工具：`tools/doc-extract.mjs`（抽取）· `tools/extract-report.mjs`（质量报告）
> 最后测量：CET-6 2013.06 – 2019.12，共 39 套

```bash
node tools/doc-extract.mjs <考期目录> --exam cet6 --report
node tools/extract-report.mjs            # 覆盖率与缺口
node tools/extract-report.mjs --full     # 逐套明细
```

## 一、先说清 L2 能做什么、不能做什么

**能**：题目、选项、阅读原文、写作/翻译题面。
**不能**：**答案与解析** —— 真题册里根本没有（实测「答案」出现 0 次）。
答案只在《答案解析》PDF 里，走 L3（`tools/ans-extract.mjs`，含 OCR 支路）。

所以候选文件是**中间态**，不是可入库的 Paper：

```
.candidates/<paperId>.draft.json   { _kind: 'candidate', questions[answer=null], passages, subjective }
        ↓ 合并答案与解析（L3）
   过闸 → content/<exam>/papers/<paperId>.json（合法 Paper）
```

另一条同样重要的事实：**听力题在真题册里只有选项、没有题干**。
听力问题是播音念的，不印在试题册上 —— 题干必须从解析册取（旧站 README 也是这么写的）。
抽取器对这类题标记 `_missing: ['stem']`，合并时若解析侧没补上就拒绝入库。

## 三、逐年排版变体（踩过的坑，后续加规则看这里）

素材横跨 7 年，排版漂移比预想的大。已适配的变体：

| 变体 | 出现年份 | 处理 |
|---|---|---|
| `Part II`（ASCII 罗马数字） | 2017+ | 正则接受 `I{1,3}V?` |
| **`PartⅡ`（全角罗马数字 U+2161）** | 2013–2016 | 正则同时接受 `[ⅠⅡⅢⅣⅤ]`；部分类型靠标题词判断，不靠数字 |
| `Directions:` 半角冒号 | 多数 | `Directions\s*[:：]` |
| `Directions：` 全角冒号 | 2013、2016 | 同上 |
| 题号与选项同行 `1. A) …` | 听力全部 | qStart 后接 optStart 即视为「选项 A」 |
| **题号与标号**无空格**`1.A.Project organizer.`** | 2016 | `qStart` 分隔符后允许零空格 |
| **选项标号全角**（`I）originated`） | 2017.12 | optStart 与 fragment 切分都接受 `）】` |
| 一行**两个选项用 TAB 分隔** | 2013–2016 | `splitOptionFragments()` 按标号位置切开 |
| 词库**一行两列用空格分隔** | 2017.12+ | 同上（fragment 切分对空格也生效） |
| **词库列间填充是 NBSP（U+00A0）**：`A)chronicles␣␣…␣␣I）perfect` | 2018.06 | fragment 切分的前缀类用 `\s`（JS 的 `\s` 覆盖 NBSP）；只认 `[\t ]` 会切不开、两项并成一项。词库接受条件按**条目数**（≥10）而非行数 —— 一行两项时 15 个词只占 8 行 |
| **选项分隔符重复**：`A). She …`（右括号后又跟句点） | 2018.06 第2/3套 | optStart / fragment 的分隔符类用 `+`，否则选项文本带出前导 `.` |
| **`Part` 抬头跨行**：`Part` / `I` / `Writing` / `(30minutes)` 各占一行 | 2018.06 第2/3套（docx「一行一段落」变体） | `stitchPartLines()` 只在「某行恰好只有 Part」时把后续碎片拼回一行；正常单行写法不触发 |
| `Questions1 to 4`（Questions 后漏空格） | 2018.06 第2套 | `qRange` 的 `Questions\s*` |
| **文件名用中文数字套号**：`…真题第二套.doc` | 2018.12 | `inferPaperId` 接受 `第?[1-3一二三]套`；只认 `第1套` 时三套会全部落到 `-1`，另两套被去重丢掉 |
| 完形空位 `__26__` | 多数 | 直接匹配 |
| **完形空位是裸数字**（`is 34    on`） | 2017.12 / 2018.06 / 2019.12 | 归一化：仅当 `__N__` 不足 8 个时把裸数字换成 `__N__`。边界必须是 `(?<![\d.])(?!\d)` —— 写成 `(?![\w.])` 会把**句末空位**（`…memory 28.`）全挡掉（2019-12-1 因此丢过整套完形） |
| 完形词库被**拆成两段且带重复**（文本框叠印） | 2019.12 | 新规则按条目数累计、允许中间空行，能跨过乱序段把 A–O 15 条拼齐 |
| `.doc` 编码 | 2013–2016 | 不用 SaveAs（ANSI/GBK 会乱码），改取 Word `Content.Text` 自己写 UTF-8 |

**一条教训**：`toHalfWidth` 之类的「全角转半角」不能对整行文字做 ——
它会把中文全角逗号转成半角，而句号不动，标点变成两套。
标号类字段单独归一，正文一律走 `cleanText`。

## 五、抽取器已修 bug（都是「静默丢数据」型，值得记）

| bug | 症状 | 根因 |
|---|---|---|
| `findDirections` 返回值恒为空 | **20+ 套的写作题面整块丢失**（`主观 —译`），少数「有值」的也是垃圾文本 | `s.replace(RE.directions, '')` —— `RE.directions` 的 `.*$` 吃掉整行，替换成空串得到 `""`（falsy）；应为 `'$1'` |
| 裸数字空位归一的前瞻过严 | 2019-12-1 整套完形丢失 | `(?![\w.])` 挡掉句末空位 `28.`；应为 `(?!\d)` |
| `extract-report` 把答案文件当候选 | 2018-06-1 被报成 **0 题**，候选套数虚增 1 | 按 `*.json` 全收，`2018-06-1.ans.json` 同 id 覆盖了真 draft；应只收 `*.draft.json` |
| `inferPaperId` 不认中文数字套号 | 2018.12 只出 1 套，另外两套被静默去重丢弃 | 只匹配 `第\s*([1-3])\s*套`，不认「第二套」 |
| 词库接受条件按行数 | 一行两项的词库（2018.06）整块丢失 | 15 个词只占 8 行，`n >= 10` 判不过；应按切分出的条目数判 |
| 选项不排序 | 往返校验必挂（导出 A,B,C,D ↔ 卷面 A,C,B,D） | 听力选项是**双栏**印刷，按行读即得 A,C,B,D；抽取末尾按标号排序 |
| 解析块行内顺序自由 | 往返校验必挂（表格是「一标签一列」，列序固定） | 顺序真源收敛到 `schema.ts` 的 `LABEL_ORDER`，迁移/合并/导出/测试四处共用 |

## 六、L3 解析 PDF：可用性普查（修正后的结论）

```bash
node tools/ans-probe.mjs --exam cet6 --years 2013-2019   # 格式普查 → docs/ans-formats.json
node tools/pdf-probe.mjs --pages 6                       # 文本层质量判定
```

### ⚠ 先修正一个早期误判

最初 `pdf-probe` 只统计**字符数量**，于是把 2017.06 判成「文本可抽」。
实际它抽出 57 万字符**全是乱码**（`౽౻౼ಂᎠ ಁᰴ๓႒㝝䄙`）——
嵌入字体缺 ToUnicode 映射，pdftotext 只能吐字形索引。

后来又发现第三类：**字符有意义但排版碎裂**（2019.12 的英文被切成每几字符一行，
`Wha / ti / st / hewoman / sp …`，单词边界全丢；bbox 坐标也救不了，
那些 PDF 的字形包围盒互相重叠）。

于是判据补齐为**三条**：

| 判定 | 条件 | 含义 |
|---|---|---|
| `text` | 字数足 + 正常字符占比 ≥0.8 + 短行占比 ≤0.5 | 真正可抽 |
| `garbled` | 正常字符占比 <0.8 | 缺 ToUnicode，字符不可用 |
| `fragmented` | 短行占比 >0.5 | 字符可用但行不成形，单词边界丢失 |
| `scanned` / `sparse` | 字数 <50 / <800 | 无文本层 / 文本极少 |

### CET-6 2013–2019 解析 PDF 实况（39 个文件）

| 状态 | 考期 | 套数 | 说明 |
|---|---|---|---|
| **可抽** | 2013.06 · 2013.12 · 2014.06 · **2018.06** | 12 | 可直接规则抽取 |
| 碎裂 | 2019.12 | 3 | 标记齐全但英文碎裂 |
| 乱码 | 2016.12 · 2017.06 · 2017.12 | 9 | 需 OCR |
| 扫描 | 2015.06 · 2015.12 · 2016.06 · 2019.06 | 12 | 需 OCR |

> 这个错误来自只量数量不量质量 —— 教训已固化成上面三条判据。

### 解析册的格式变体（数据驱动，非猜测）

`ans-probe.mjs` 统计每份文件的标记词与题号写法，结果见 `docs/ans-formats.json`：

| 考期 | 字数 | 碎片 | 主要标记词 |
|---|---|---|---|
| 2013.06 | 27k | 0.05 | `答案×80` `定位` `预测` `问题` `解析` `详解` |
| 2013.12 | 26k | 0.05 | `答案×71` `定位` `预测` `干扰项` |
| 2014.06 | 27k | 0.03 | `答案` `预测` `详解` `答案与详解` |
| 2017.12 | 156k | 0.14 | `问题×66` `答案×49` `词汇` `定位` `语法` |
| **2018.06** | 40k | **0.01** | `答案×105` `详解` `定位` `译文` `点睛`（最干净） |
| 2019.12 | 41k | 0.20 | `问题` `预测` `答案` `解析` `定位` |

**题号写法也逐年在变**：2013–2014 主导是**顿号**（`1、`），
2018+ 是 `1:` 或 `1.`，另有 `【1】` / `(1)` / `第1题` 的零星用法。
所以 L3 的切分规则同样要**按考期分组配置**，和 L2 一样。

### 各格式的样例（写规则时对照）

**2018.06**（最干净，建议先做这个）
```
Conversation One
M: What's all that? …
Questions 1 to 4 are based on the conversation you have just heard.
未听先知：预览四道题各选项…
1: What do we learn about gazpacho?        ← 题干（英文）
答案：B                                      ← 答案
详解：对话中，女士清楚地解释说…因此答案为 B。   ← 解析
```

**2019.12**（标记齐全但英文碎裂）
```
[预测]各项核心关键词"记者"、"设计师"…
[问题]What is the woman's profession? (女士的职业是什么?)   ← 英文碎裂
[解析]D)复现开篇对女士的身份介绍(works as Features Editor)。  ← 答案在解析开头
```

**2013.06 / 2013.12 / 2014.06**：`答案` / `定位` / `预测` / `问题` / `解析` 混用，题号以顿号为主。
