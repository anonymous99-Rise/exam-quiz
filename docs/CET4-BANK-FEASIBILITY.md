# 四级题库可行性报告（方案 A 第一阶段）

> 素材：`.sources/CET6-Resources/CET4_`（14 个考期 / 81 个 PDF / 21 docx / 21 doc / 3 MP3）
> 管线：`tools/inventory.mjs` → `doc-extract.mjs` → `ans-extract.mjs` → `bank-merge.mjs` → `bank-validate.mjs`

## 一、已解决：信息匹配段抽不出来（0/10 → 10/10）

**现象**：`doc-extract.mjs --exam cet4` 抽 2019-12-1 只得 44 题，其中**匹配 0/10**，
警告「匹配：只切出 0 段，疑似失败」。

**根因**（不是正则不通，是信息不在文字层）：

四级素材的信息匹配段用 **Word 自动编号列表**当段落标签：

| 段落 | Word 的存储方式 | 文字层里看得到吗 |
| --- | --- | --- |
| 匹配段落 A)–K) | `<w:numPr>` → numId=2 → `numFmt=upperLetter`, `lvlText=%1)` | **看不到**（标签是自动生成的） |
| 陈述句 36.–45. | `<w:numPr>` → numId=3 → `numFmt=decimal`, `lvlText=%1.` | **看不到**（连题号也没有） |

所以 `stripXml` 之后，段落全成了无标记的普通段落 —— 靠文字里的 `A)` 去找永远找不到。

**修法**：新增 `docxListMeta(file)`，解析 `word/document.xml` 的 `<w:numPr>` +
`word/numbering.xml` 的格式定义，得到「段落文字 → {numId, numFmt, start}」映射；
`extractMatching` 在文字层找不到 A)–O) 时回退到这条通道，按列表顺序还原标签。

**为什么不用「按顺序硬编号」的偷懒做法**：同一份文档里听力选项也是列表（numId=1），
匹配段落与陈述句是另外两个列表 —— 只有读元数据才能精确分开，硬编号会把听力选项也算进去。

**验证**：

```
修前：2019-12-1 → 44 题  听力24 完形10 匹配 0 阅读10
修后：2019-12-1 → 54 题  听力24 完形10 匹配10 阅读10
      ⚠ 匹配：文字层无 A)–O) 标记，已按 Word 自动编号还原 11 段（A–K）
回归：bank-roundtrip --exam cet6 --all → 47 套全部一致（未受影响）
      重抽六级 2019-12-1 → 55/55 无警告（六级本身有 A) 文字标记，走原路径）
```

补丁是**通用**的（不写死四级），任何用自动编号的 Word 试卷都受益。

## 二、卡点：答案抽不出来（数据问题，非工具问题）

**现象**：`ans-extract.mjs <解析 PDF> --paper 2019-12-1` → 「抽到答案 1 题，自检未过」。

**根因**：这份解析 PDF 的文字层是**扫描件的劣质 OCR 结果**：

```
影案验答案详解频偿税，液热器系来态          ← 水印被 OCR 混进正文
１． Ｗｈａｔ ｈａｐｐｅｎｅｄ ｉｎ Ｎｅｗ Ｙｏｒｋ＇ｓ…   ← 全角拉丁 + 全角题号
```

没有 `【答案】`、没有 `1. A` 这类结构标记 —— 只有 26 处散落在解析正文里的「答案为」。
把它当文字版用会得到**错误的答案**，比没有答案更坏。

## 三、全考期普查（决定批量范围）

| 考期 | 真题（可抽题） | 解析文字层 | 判定 |
| --- | --- | --- | --- |
| 2014.06 / 2014.12 / 2015.06 / 2015.12 | docx/doc ✅ | 11k–12k 字 | ⚠️ 有文字但需逐份验质量 |
| 2016.06 | docx ✅ | 10k 字 | ⚠️ 同上 |
| 2016.12 | docx ✅ | **0 字** | ❌ 纯扫描 |
| 2017.06 / 2017.12 / 2018.06 | docx ✅ | 13k–15k 字 | ⚠️ 同上 |
| 2018.12 | docx ✅ | **282 字** | ❌ 纯扫描 |
| 2019.06 / 2019.12 | docx ✅ | 9k–14k 字 | ❌ **文字层是 OCR 垃圾**（已实测） |
| 2024.12 / 2025.06 | **只有扫描 PDF** | 0–8 字 | ❌ 需 OCR |

结论：**题面可抽（docx 干净）**，但**答案与解析的来源不可靠** —— 要么是扫描件，
要么是劣质 OCR 文字层。四级题库的真正瓶颈在答案侧。

## 四、可选路径（需要决策）

| 路径 | 做法 | 代价 | 风险 |
| --- | --- | --- | --- |
| **A1. OCR 攻坚** | 用 tesseract（中文）重跑解析 PDF，再按结构抽答案 | 30 套 × 20 页 OCR + 逐套人工抽查 | 水印干扰；答案错一位就是灾难，必须逐套核对 |
| **A2. 换答案源** | 另找结构化答案（公开数据集 / 官方答案页），与 docx 题面对齐 | 需评估来源可信度 | 来源不可信则同样不能用 |
| **A3. 先上题面** | 只入库**题面 + 原文**，答案标 `pending`，UI 明确标注「本套暂无答案与解析」 | 小 | 站内原则允许（缺口如实标注），但没有判分的刷题价值 |
| **A4. 搁置** | 四级继续用上游真题例句信号做「真题优先」排序（已上线，60% 覆盖） | 0 | — |

**建议 A2 → A1**：先花一轮找可信的结构化答案源（例如同一素材库里的其他格式、
或公开的四六级答案数据集）；找到就直接对齐，找不到再评估 OCR 的投入产出。
